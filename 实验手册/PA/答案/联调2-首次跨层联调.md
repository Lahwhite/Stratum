## 二、确认 UART 外设地址

**这是此次联调最关键的一步**：双方需要对齐 UART 寄存器的物理地址。

由成员 A 在 SCore 中定义，写入共享头文件：

创建（或更新）`score/include/mmio.h`：

```cpp
#pragma once
#include <cstdint>

// Memory-Mapped I/O 地址表
// 所有外设寄存器地址在此统一定义，双方共用
#define UART_TX_ADDR   0xa0000000u   // 串口发送寄存器（写 1 字节 → 终端输出）
#define TIMER_LO_ADDR  0xa0000048u   // 定时器低 32 位（microseconds）
#define TIMER_HI_ADDR  0xa000004cu   // 定时器高 32 位
```

成员 A 在 SCore 的内存访问路径中拦截这些地址：

在 `score/src/memory/memory.cpp` 的 `paddr_read/paddr_write` 中，加入 MMIO 分发：

```cpp
#include "mmio.h"
#include <cstdio>
#include <ctime>

// MMIO 写处理
static void mmio_write(uint32_t addr, int len, uint32_t data) {
    if (addr == UART_TX_ADDR) {
        putchar((char)(data & 0xff));
        fflush(stdout);
    }
    // PA3 阶段添加 VGA / 键盘
}

// MMIO 读处理
static uint32_t mmio_read(uint32_t addr, int len) {
    if (addr == TIMER_LO_ADDR) {
        struct timespec ts;
        clock_gettime(CLOCK_MONOTONIC, &ts);
        uint64_t us = (uint64_t)ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
        return (uint32_t)(us & 0xffffffff);
    }
    if (addr == TIMER_HI_ADDR) {
        struct timespec ts;
        clock_gettime(CLOCK_MONOTONIC, &ts);
        uint64_t us = (uint64_t)ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
        return (uint32_t)(us >> 32);
    }
    return 0;
}

// 在 paddr_read 开头插入 MMIO 检查
uint32_t paddr_read(uint32_t addr, int len) {
    if (addr >= 0xa0000000u) return mmio_read(addr, len);
    // ... 原有内存读逻辑
}

void paddr_write(uint32_t addr, int len, uint32_t data) {
    if (addr >= 0xa0000000u) { mmio_write(addr, len, data); return; }
    // ... 原有内存写逻辑
}
```

成员 B 在 SHAL 的 riscv 平台实现中使用同样地址：

创建 `shal/src/riscv/ioe.cpp`（此文件联调时由 B 创建）：

```cpp
#include "am.h"
#include "amdev.h"

// 写 MMIO 寄存器
static inline void outb(uint32_t addr, uint8_t val) {
    *(volatile uint8_t*)addr = val;
}
static inline uint32_t inw(uint32_t addr) {
    return *(volatile uint32_t*)addr;
}

bool ioe_init() { return true; }

void ioe_read(uintptr_t reg, void *buf) {
    switch (reg) {
        case AM_TIMER_UPTIME: {
            uint32_t lo = inw(0xa0000048u);
            uint32_t hi = inw(0xa000004cu);
            ((AM_TIMER_UPTIME_T*)buf)->us = ((uint64_t)hi << 32) | lo;
            break;
        }
    }
}

void ioe_write(uintptr_t reg, const void *buf) {
    switch (reg) {
        case AM_UART_TX:
            outb(0xa0000000u, ((AM_UART_TX_T*)buf)->data);
            break;
    }
}
```

## 三、联调测试步骤

### Step 1：最简汇编测试

编译 B 准备的 `hello.S`：

```bash
cd stratum-apps/apps/hello
riscv32-unknown-elf-gcc -march=rv32im -mabi=ilp32 -nostdlib \
    -T ../../cpu-tests/link.ld hello.S -o hello.elf
```

在 SCore 上运行：

```bash
./score/score -e stratum-apps/apps/hello/hello.elf
```

**期望结果**：终端打印 `Hi` 并换行，然后程序因 ebreak 停机，SDB 提示符出现。

若没有输出，排查顺序：
1. A：确认 MMIO 拦截逻辑已正确插入 `paddr_write`
2. B：确认 `hello.S` 中写入的地址与 `mmio.h` 一致
3. A：在 SDB 中用 `x 1 0xa0000000` 查看 UART 寄存器值

### Step 2：klib printf 测试

编译一个用 klib `printf` 的 C 程序：

```bash
# 在 stratum-apps/apps/hello/ 下创建 hello_c.c
cat > stratum-apps/apps/hello/hello_c.c << 'EOF'
#include <stdio.h>   // 使用 klib 的 printf

int main() {
    printf("Hello from Stratum!\n");
    printf("1 + 1 = %d\n", 1 + 1);
    return 0;
}
EOF
```

需要 `_start` 引导：

```asm
# stratum-apps/apps/hello/start.S
.section .text
.globl _start
_start:
    la   sp, _stack_top   # 设置栈指针
    call main
    ebreak

.section .bss
.align 4
.space 4096
_stack_top:
```

编译：

```bash
riscv32-unknown-elf-gcc -march=rv32im -mabi=ilp32 -nostdlib \
    -Ishal/klib/include \
    stratum-apps/apps/hello/start.S \
    stratum-apps/apps/hello/hello_c.c \
    shal/klib/src/string.cpp shal/klib/src/stdio.cpp shal/klib/src/stdlib.cpp \
    shal/src/riscv/ioe.cpp \
    -T stratum-apps/cpu-tests/link.ld \
    -o stratum-apps/apps/hello/hello_c.elf
```

运行：

```bash
./score/score -e stratum-apps/apps/hello/hello_c.elf
```

**期望输出**：

```
Hello from Stratum!
1 + 1 = 2
```

### Step 3：用 SDB 调试一次失败场景（练习）

故意让程序访问非法地址，观察 SDB 的错误提示：

```
(sdb) si 100
非法内存读：addr=0x00000000 len=4
```

确认错误处理不会崩溃，SDB 仍然响应命令。
